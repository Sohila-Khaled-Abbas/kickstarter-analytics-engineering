## Phase 4: Advanced Deduplication (`Table.Buffer`)

You now have a massive table containing millions of rows. A single project (e.g., an Oculus Rift campaign) might exist in Kaggle 2016 (as "live"), Kaggle 2018 (as "successful"), Kaggle Master, and WebRobots. 

If you just click "Remove Duplicates" in the GUI, Power Query's "Lazy Evaluation" will ignore your sorting and keep a random row. You must force the engine to keep the absolute latest state using M-Code.

* **M Code (Advanced Editor):**
  Open the Advanced Editor for `Fact_Campaigns_Raw` and replace the final steps with this logic:

  ```powerquery
      // 1. Sort Descending by Date (Keep newest update)
      // Note: If you have a 'state_changed_at' or 'updated_at' column, use that. Otherwise, 'launched_at' or 'deadline_at' ensures consistency.
      SortedRows = Table.Sort(PreviousStepName,{{"deadline_at", Order.Descending}}),
  
      // 2. Buffer the table in memory to FORCE the engine to respect the sort order.
      BufferedTable = Table.Buffer(SortedRows),
  
      // 3. Remove duplicates based on Project ID. Keeps the top (newest) row!
      Deduplicated = Table.Distinct(BufferedTable, {"project_id"})
  in
      Deduplicated
  ```

## Phase 5: Dimensional Modeling (Star Schema)

VertiPaq thrives on narrow Fact tables (numbers/dates) and distinct Dimension tables (text). We must break apart `Fact_Campaigns_Raw`.

### 1. Build Dimensions (Reference `Fact_Campaigns_Raw` to create these)
Right-click `Fact_Campaigns_Raw` and select **Reference**.
* **`Dim_Category`:** Keep only `category_name` and `subcategory_name`. Remove Duplicates. Add an Index column named `category_id`.
* **`Dim_Location`:** Keep only `country`, `state`, and `county/subregion`. Remove Duplicates. Add an Index column named `location_id`.

### 2. Create the Final Fact Table
1. Reference `Fact_Campaigns_Raw` one last time. Name it `Fact_Campaigns`.
2. **Merge** with `Dim_Category` (matching on category strings) and `Dim_Location` (matching on location strings) to bring in `category_id` and `location_id`.
3. **CRITICAL:** Delete all heavy text columns (`category_name`, `country`, `subcategory_name`, etc.) from the Fact table. Only keep `project_id`, the new `_id` foreign keys, Dates, and numeric metrics (Goal, Pledged, Backers).

### 3. Build a Date Dimension (M-Code)
Create a Blank Query, open the Advanced Editor, and paste this standard Date script for Time Intelligence DAX:
```powerquery
= List.Dates(#date(2009,1,1), Duration.Days(DateTime.Date(DateTime.LocalNow()) - #date(2009,1,1)), #duration(1,0,0,0))
// Convert to table, change type to Date, rename column to [Date]. Extract Year, Month Name, Month Number via the GUI.
```
Name it `Dim_Date`. **Check "Enable Load" for this query, your dimensions, and Fact_Campaigns.**

## Phase 6: The Semantic Layer (DAX & Relationships)

Click **Close & Apply**. The Mashup Engine will execute the python-enriched files, stack the Kaggle files, buffer them in RAM, drop millions of duplicates, and load the optimized Star Schema.

Go to the **Model View** and build your Snowflake schema:

1. **Core Relationships:**
   * `Dim_Category[category_id]` -1:M-> `Fact_Campaigns[category_id]`
   * `Dim_Location[location_id]` -1:M-> `Fact_Campaigns[location_id]`
   * `Dim_Date[Date]` -1:M-> `Fact_Campaigns[launched_at]`
2. **Snowflake the Metrics (The Kaggle Aggregations):**
   * Link `Dim_State_Metrics[State]` -1:M-> `Dim_Location[state]` 
   * Link `Dim_County_Metrics[subregion]` -1:M-> `Dim_Location[county/subregion]`
3. **UI / UX Polish:**
   * Select all `_id` columns across all tables. Turn on **Is Hidden**. End-users should filter by text names, never ID numbers.
   * Format `pledged_usd` and `goal_usd` as Currency ($) with 0 decimal places.
